Notification Service • Port 8085 • Backend-only RabbitMQ consumer

📡 How Notifications Work

The Notification Service is a backend-only consumer. It listens to RabbitMQ queues and processes events like user registrations, ride updates, and payment completions. There is no HTTP API — all notifications are consumed from message queues.

💡 To see notification logs: Run docker compose logs -f notification-service in your terminal.

📬 Message Queues

Events flow through these RabbitMQ queues

  • 👤
    USER_EVENTS_QUEUE
    USER_REGISTERED, USER_LOGGED_IN events from User Service
  • 🚗
    RIDE_EVENTS_QUEUE
    Ride lifecycle events from Ride Service
  • 💰
    PAYMENT_EVENTS_QUEUE
    PAYMENT_SUCCESS events from Payment Service

🔄 System Flow

End-to-end ride booking flow

1
User registers / logs in
POST /api/users/register → User Service → event to USER_EVENTS_QUEUE
2
User books a ride
POST /api/rides → Ride Service → stored in Redis → published to Redis Pub/Sub "ride_requests"
3
Drivers receive ride via WebSocket
Driver Service subscribes to Redis Pub/Sub → broadcasts NEW_RIDE to online drivers in zone
4
Driver accepts the ride
ACCEPT_RIDE via WebSocket → Redis SETNX atomic lock → first driver wins
5
Payment is processed
POST /api/payments → Payment Service → PAYMENT_SUCCESS to NOTIFICATIONS queue
6
Notification Service consumes events
Logs events from all queues. Failed messages → DLQ (Dead Letter Queue)
